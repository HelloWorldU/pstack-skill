# 体验优先

当实现便利与用户愉悦冲突时，选择愉悦。

- 每个功能、控件、选项都必须有存在的理由
- 少做，做好（三个功能打磨到位，胜过十个功能粗制滥造）
- 先原型再定稿（在用后即弃的 HTML 里做设计决策，比在生产代码里做便宜得多）
- 把细节做对（过渡动画、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能要么服务于中心工作流，要么就让路）

用户就是消费这份产出的人。对 UI 来说，那是终端用户。对库或内部 API 来说，那是 import 它的同事。下一个维护这段代码的工程师也是用户。用同样的标准衡量他们的体验，并从他们的视角解释影响。

地基应当为体验服务。地基思维管的是工作的*顺序*，这条原则管的是*目标*。
