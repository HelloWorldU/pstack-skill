# 先迁移调用方，再删除遗留 API

当我们认定新 API 是正确设计时，就在同一波重构里迁移调用方并移除旧 API，而不是保留兼容层。

**规则：**
- 不要仅仅因为内部调用方还存在就保留旧 API 路径
- 清点调用方，迁移它们，立即删除旧 API
- 把临时适配器视为例外且有时限的东西，而不是默认架构
- 更新测试去断言新契约，删掉那些只在保护重构前实现细节的测试

**何时适用：**
- 没有外部用户依赖向后兼容
- 项目消化得了协调一致的破坏性变更
- 新 API 属于某个简化或重构计划的一部分

新旧 API 并存会制造双路径复杂度，拖慢清理，让整个代码库有种只增不减的感觉。
