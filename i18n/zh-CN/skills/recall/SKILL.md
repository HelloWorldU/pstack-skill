# Recall

**在你开始或恢复工作之前，重建用户最近的工作上下文，并交回一份紧凑的胶囊式简报：现在进展到哪、接下来该做什么。**

保持紧凑、紧扣主题。只读范围内线程所需的内容，然后收手。

你的上下文分布在两份记录里。你自己的聊天记录保存着你做过什么、决定了什么。共享记录保存着同一份代码周围以其他名义发生的一切：用户反复报告的症状、上线了又被回滚的修复、仍在生产环境触发的错误。第二份记录正是 **why** 技能搜索的对象——横跨源代码管理、工单追踪器、聊天与工单频道、长篇文档和错误追踪。一个拖着长长 bug 尾巴的功能，大半故事都在那里，所以不要只凭自己的聊天转录来重建它。

转录文件位于 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是去掉开头斜杠、并把每个 "/" 换成 "-" 之后的工作区路径（所以 `/Users/you/proj` 变成 `Users-you-proj`）。每一行就是一条聊天消息。

1. 先分类，再路由。要恢复某一个具体的历史聊天，那是 `session-pickup` 行动手册的事，不是本技能。把习惯沉淀为持久技能是 `automate-me`。给你的工作产出一份人可读的总结又是另一项任务。Recall 是在你行动之前，跨近期聊天加载工作上下文。如果用户已经给了你完整的状态胶囊（路径、分支、改动），直接用它，跳过挖掘。
2. 搜索前先锁定范围。钉住时间窗口（「recent」必须是一个真实区间，默认最近 7 天）、被点名的主题（如果有）、以及工作区（默认当前活动工作区。未经要求，绝不读其他项目的转录）。把范围复述给用户。绝不悄悄把「all」变成「最近 N 条」。
3. 在你的聊天记录上扇出。派生多个并行子代理，跑在快速、便宜的模型上，每个负责语料的一个切片。告诉每个子代理：按真实修改时间排序候选文件（`ls -t`），绝不按 UUID 名称排序；先按主题 grep，然后只读命中的聊天、且只读其中相关的区段；跳过当前聊天和明显的噪音（子代理、评测、测试聊天）。每个子代理返回同一套结构，每个聊天一块：主题、用户的目标、决策、未完结的线索、踩过的坑与纠正、以及产物（PR、工单、分支），每条都标注聊天 UUID。只有一两个聊天时，跳过扇出，直接搜索。原始转录留在子代理手里，主线程只拿它们的发现。每个子代理的推理档位和快速或标准速度，按 **poteto-mode** 技能的 Subagents 一节为这项任务来挑。
4. 只要主题点名了某个功能、文件、子系统、领域或 bug，就扫一遍共享记录。这是默认动作，不是酌情判断，「我在 X 上的工作」也不能豁免。把它交给 **why** 技能的各来源调查员，但把他们的问题从「当初为什么这么建」引导到「现在是什么状态、试过什么但没站住、用户还在报告什么」。复用它的各来源行动手册，让调查员与聊天记录挖掘并行运行，并继承它的姿态：每个来源一名调查员，空结果也是发现，某个 MCP 不可用就跳过并明说。把回来的结果并入简报。只有纯活动回顾、没有点名目标时才跳过这一步（「我这周做了什么」）——那时你自己的历史和实时状态就是全部答案。
5. 对照实时状态核实。把挖掘和扫描浮出水面的 PR、分支、工单，用 `git` 和 `gh` 查证。当答案取决于某个代理实际做了什么（它跑了哪些工具、读了哪些文件、撞上了哪些错误）时，读完整转录，而不是只读本地裁剪过的副本。
6. 按下面的契约写简报。按线程分组。始终扣住被点名的主题。

## 输出契约

先给胶囊，再给线程状态，再给问题，最后给下一步。更深的细节放到下面，或者直接砍掉。

- **胶囊。** 最多 5 条要点。这项工作是什么、整体进展到哪。
- **线程。** 每条一行，行首恰好一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没有标签的线程就不算完结，所以给它打上标签。
- **问题。** 最多 5 个，取反复出现的那些。要包含用户反复报告的症状，以及任何上线了又被回滚的修复，好让下一次尝试从上一次失败的地方起步。
- **下一步。** 最有用的单一动作，要具体。

相邻的功能或工单留在外面，除非它阻塞了当前这条。当胶囊和线程行超出一屏时，先砍细节，别砍线程。通过 **unslop** 技能来写这份简报；来自聊天的发现按 UUID 引用，来自共享记录的发现按来源引用（PR 号、工单 ID、聊天永久链接、错误追踪 issue）；任何对外输出之前先脱敏私有上下文。

**回复：** 按上面的契约给出简报。
