# 解释这个数字

- **问「为什么没有翻倍？」** 说出限制结果的那个资源或代码路径，比如一个核、一把锁、磁盘、网络，或者负载生成器本身。依据要来自 profile 或运行期间采集的系统计数器，然后再映射回源码。靠读代码猜出来的不算限制因素。如果你说不清为什么这个数字不是现在的两倍好，你就不知道自己测的是什么。
- **列出这个数字还可能在测什么，并用证据逐一排除。** 常见的嫌疑对象有：错误、被跳过或被缓存的工作、根本没跑到的代码、没调优的一方（一方还停在默认配置）、噪声，以及小到极致、端到端无关紧要的一段。
- **把证据和数字放在一起。** 把运行次数、离散程度和限制因素写进备注或链接的产物里。

对性能数字，用 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能跑完整流程。对评测结果，对每一轮试验问同样的问题：每次运行都真的做了任务吗？差距在不同试验、不同模型间稳定吗？这个场景重要吗？

只要一个数字背后的证据没有运行次数、没有离散程度、没有指名的限制因素，或者省下的时间比被改动的那段本身耗时还长，你就跳过了这条原则。

与[证明它有效](../principle-prove-it-works/SKILL.md)不同——那条检查的是产出是否真实。
