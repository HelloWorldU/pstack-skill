# Bugbot 分流

当 Babysit 行动手册（`../playbooks/babysit.md`）处理 Bugbot 或评审自动化的评论时，使用本参考。目标不是默认无视 Bugbot，而是不再把每条评论都当作必须改的代码。

## 决策准则

行动之前，先对每条 Bugbot 讨论串分类：

- `fix`：评论指出了一个可信的正确性、安全、隐私、数据丢失、鉴权、计费、迁移、幂等、竞态或已发布行为问题。在归属层级最低的 PR 里修复，然后回复提交 SHA 并解决该讨论串。
- `dismiss`：评论匹配一个记录在案的低风险噪声模式，且当前代码/上下文证明该顾虑不需要改代码。回复一条简短理由并解决该讨论串。
- `ask`：评论是新奇的、高严重度的、涉及安全/隐私/数据的，或含糊不清。问用户，不要猜。

拿不准就问。跳过一条噪声的代码质量评论代价很低；跳过一个真实的数据或安全 bug 代价不低。

## 习得模式的格式

未来的模式按这个形状添加：

```markdown
### <short pattern name>

- Confidence: candidate | recurring | strong
- Skip when: <conditions that must be true>
- Do not skip when: <risk boundaries>
- Example signal: <phrases or code context that identify the pattern>
- Source: <PR/comment URL or short historical note>
```

只有一两个例子时用 `candidate`。经过多次真实驳回后用 `recurring`。只有当模式狭窄、被反复验证且低风险时才用 `strong`。

## 反复出现的可跳过候选

### 有意的 UI 或设计系统视觉变更

- 置信度：candidate
- 跳过条件：PR 描述、截图、设计评审或邻近代码已明确表达这个视觉变更，而 Bugbot 的评论只是在复述一个共享的视觉默认值变了。
- 不可跳过：评论指向无障碍、焦点可见性、键盘导航、颜色对比度，或 PR 没有意图改动的组件 API 契约。
- 示例信号：关于焦点轮廓、按钮尺寸、间距或共享组件视觉默认值的评论，且负责人回复了 "intentional" 或 "intended"。

### Bugbot 看不到的栈上层或栈内局部使用

- 置信度：candidate
- 跳过条件：Bugbot 把一个导出、组件、辅助函数或文件标记为未使用，而当前 forge 的 PR 列表和 diff、栈上层 diff 或 PR 上下文显示它被栈中靠后的 PR 使用。
- 不可跳过：当前 PR 不属于某个栈、符号是公开 API，或所谓的栈上层使用无法验证。
- 示例信号："Exported component is never used"，且有人类回复类似 "used upstack"。

### 并行实现期间的临时重复

- 置信度：candidate
- 跳过条件：PR 有意重复了一小段代码，以让新路径与一条正在删除、替换或验证中的旧路径保持并行。
- 不可跳过：重复的代码涉及安全、计费、数据访问、API 行为，或一个长生命周期的共享抽象显然能降低风险。
- 示例信号："Significant duplication" 或 "duplicated validation logic"，且负责人解释了旧路径将被删除，或重复逻辑是有意保持局部的。

### 现有框架或组件不变量已覆盖该警告

- 置信度：candidate
- 跳过条件：该顾虑已经被当前 diff 或邻近代码中可见的共享组件、框架契约、类型不变量或单一事实来源保证。
- 不可跳过：不变量只是被假定而没有被强制、依赖时序，或跨越可能让值发散的 async/状态边界。
- 示例信号：关于内层 popover 缺少 max-height 的评论，而共享 popover 已强制视口边界；或针对可空值的评论，但本地检查过的值和传入的值来自同一来源。

### 负责人声明的后续跟进或延期清理

- 置信度：candidate
- 跳过条件：PR 负责人明确表示该问题是已知的后续项，当前 PR 没有让行为变差，且评论不涉及高风险区域。
- 不可跳过：代理在没有负责人意见的情况下行动、问题是中/高严重度的产品行为，或延期会把一个新回归合并进去。
- 示例信号："I'll worry about that later" 或 "we'll delete this eventually"。

### 自我撤回或明确误报的规则评论

- 置信度：recurring
- 跳过条件：评论正文或后续 Bugbot 回复明确表示该发现被撤回、已合规或是误报，且代理能在本地验证相关规则。
- 不可跳过：唯一证据是某个人在高风险问题上说了一句「误报」而没有解释。
- 示例信号：一条文件命名规则评论，其正文说该文件已经合规。

## 默认要问

以下类别不要自动跳过，即便之前的 PR 驳回过类似的：

- 安全、隐私、鉴权、计费、数据保留、训练数据和权限边界的发现。
- 高严重度发现。
- 迁移、schema、幂等、并发和跨系统行为的发现。
- 建议的修复很小、且显然能在不改变产品意图的前提下降低风险的评论。

历史数据表明，人类有时会驳回安全/数据流评论。把那些当作负责人的个人判断，而不是全团队的跳过规则。

## 最近 babysit 中的候选经验

在 babysit 期间或之后，把看起来对团队有用但还不成熟的新候选经验追加到这里。一旦有几个 PR 确认了模式，优先把反复出现的候选晋升到上一节。

### 手工重新实现浏览器原生行为

- 置信度：candidate
- 跳过条件：实际上几乎从不。当 diff 用手工等价物替换浏览器原生行为时（原生 sticky → JS 定位的克隆、原生滚动定位 → 转发的 wheel/touch 事件、绘制顺序遮挡 → mask/clip-path），Bugbot 针对这类代码的逻辑 bug 发现一直被证明是成立的。
- 不可跳过：发现涉及事件转发缺口（wheel deltaMode、触摸平移、边缘滚动链、tap 容差）、mask/clip 命中测试分歧，或这类代码中 observer 与 React 状态的时序竞态。默认修复。
- 示例信号："masks do not affect hit-testing"、"overlay blocks wheel scroll"、"ignores deltaMode"、"runs in the IntersectionObserver callback before React applies state"。
- 来源：一个 sticky 遮挡 PR：六轮 Bugbot 检查，大约十八条发现，每一条都是修复而非驳回。

### 契约测试漂移的论断验证成本很低——先跑测试

- 置信度：candidate
- 跳过条件：验证本身永不跳过；它只要一条命令。当 PR 交付一个钉住协议或文档文字的契约测试（对 SKILL.md 的正则、文档措辞的快照），而 Bugbot 声称「测试不再匹配文档」（或反过来）时，先在 PR 顶端跑那个测试再分类。红灯实证了该论断；绿灯是给驳回回复的具体反证。
- 不可跳过：n/a——这是一条验证捷径，不是驳回模式。注意「重复通过就倾向驳回」的启发式在这里会误伤：钉住文字的测试之所以漂移，恰恰是因为之前的修复轮改了文字。
- 示例信号："Contract test omits the pre-fix wait"，出现在一个早期修复提交改写了被钉住段落的 PR 上；在顶端跑测试，恰好失败在被引用的那条断言上。
- 来源：一个钉文字的 PR，八轮 Bugbot 检查；该论断在第 7 轮是真的，尽管之前每一轮都已修复并解决。

### 已在同一 PR 后续修复的过期安全评审发现

- 置信度：candidate
- 跳过条件：代理式安全评审（或类似物）声称缺少 authz/校验调用，而当前 PR 顶端显然包含那个确切的闸口（带测试），通常是评审运行之后在后续加固提交里加的。
- 不可跳过：被引用的辅助函数对所讨论的 principal 是空操作、检查跑在它守护的副作用之后，或对所声称的 principal 缺少覆盖。
- 示例信号：一条 HIGH 级「缺少授权检查」发现，而确切的守护在顶端已在副作用之前调用。
- 来源：一个 webhook 端点 PR，其加固提交晚于评审运行。

### 把有意收窄的错误条件放宽会掩盖真正的错误

- 置信度：candidate
- 跳过条件：发现要求把收窄的错误条件（特定 `errno`、错误码或状态类别）放宽成兜底，而这种收窄编码了一个真实区分。典型形态是门控在 `ENOENT` 上的依赖回退：「二进制未安装」与「命令运行了但失败」是两种不同情形。对任何非零退出都重试，会把一次合法失败（未找到、鉴权过期、网络）对着回退再跑一遍，然后报告回退的错误，把真正的错误藏起来。
- 不可跳过：收窄的条件漏掉了同一类别的情形（另一个「二进制不可用」的 errno，如 `EACCES`，或另一种传输层失败）、未处理路径会丢数据或留下半截状态，或者重试是幂等的且原始错误仍会被呈报。
- 示例信号："only retries when X fails with ENOENT … never tries the fallback even when a working Y exists"，指向的代码其回退是为缺失依赖而非失败操作准备的。
- 来源：一个 CLI 改名 PR，其回退是为缺失二进制而非失败命令准备的。
