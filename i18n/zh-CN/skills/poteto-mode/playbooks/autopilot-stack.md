### 堆叠自动驾驶（Autopilot-stack）

**你拥有这个堆叠，但永远不拥有落地。把一串基座相连的线性 PR 堆叠交给操作员去评审和落地。** 除"已验证的工作如何离场"之外，**Autopilot-full** 全部适用。每个 tick 从主干重读两本行动手册，两者不一致时以本手册为准。

1. **运行 Autopilot-full 的负责人机制，但去掉落地环节。** 负责人报告 STACK-READY 来代替 merge-ready。它们从不变基到任何其他分支——包括主干——也从不改挂目标、合并、关闭 PR 或启用自动合并，因为链的拓扑归根代理所有，落地归操作员所有。当某个条目依赖另一个条目时，它的负责人从那个条目的分支切出来，而不是从主干。
2. **拓扑只设一个写入者。** 负责人只推送自己的分支，并报告每个分支顶端及其预期的父级。只有你可以变基或改挂某个链节，因为同一条链上的两个写入者会互相抵消。按依赖顺序追加每个干净的 PR，把它的基座设为父级的分支（`origin pr edit <pr> --base <parent-branch>` 或 `gh pr edit <pr> --base <parent-branch>`）。永远不要要求 `gt`。负责人把你的推送当作它的新基座和租约；遇到冲突时，它解决自己那一片，交给你推送。
3. **在根层级吸收漂移。** 落地开始之前，对每一个链节应用 Autopilot-full 第 5 步的检验，在它要求变基的地方自底向上变基整条链。然后逐链节应用 patch-id 规则，因为一个链节的基座就是它的父级。
4. **交付这条链，然后把手拿开。** 每个链节的判定随它的 PR 携带。落地一旦开始，除了 `playbooks/shipping.md` 批准的合并后改挂之外，谁都不许写这条链——因为第二个写入者会破坏进行中的落地。落地途中出现的问题经你转达给操作员，任何修复都等操作员放行。

**在两种自动驾驶之间做选择。** PR 相互独立且已授予落地权限时用 Autopilot-full；操作员想在落地前评审、工作有先后次序或相互耦合、或未授予合并权限时用 Autopilot-stack。

**回复：** 按 **ketchup** 技能让操作员跟上进度，附上堆叠根部和顶端的链接、每个链节的一行判定，以及任何被搁置或排除的事项及其原因。
