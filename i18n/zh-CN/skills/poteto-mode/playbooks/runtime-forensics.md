### 运行时取证

**你拥有诊断。给活进程插桩，不要从源码推测。** 交付物是带引用的诊断，不是修复。

1. 通过控制技能在匹配表面上捕获活信号：对空转的进程做 CPU profile，对泄漏做堆快照，对视觉故障做 CDP trace。要真实工件，不要猜测。
2. 把工件归约到确凿证据：热路径上的函数、从泄漏对象到 GC root 的 retainer 链、无输入却在触发的循环。在子代理中解析大工件（**guard-the-context-window** 原则技能），把归约后的发现留在主线程。按 Subagents 一节为每个子代理选择适合任务的推理等级和 fast 或 standard 速度。
3. 在相信机制之前先证明它。通过 CDP eval 向运行中的进程注入插桩，或不重载地热修补活代码，廉价地确认假设。
4. 把发现映射回源码：文件、符号、分配或调度发生的那一行。
5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 捕获的信号、归约后的发现、你如何证明机制、源码位置、工件路径。除非被要求，不给修复。原因已知后交回 Bug fix 或 Perf。
