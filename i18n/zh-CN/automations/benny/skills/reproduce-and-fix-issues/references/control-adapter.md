# 控制适配器契约

Benny 并不知道如何启动和驱动每一个应用。用户必须配置一个为目标应用实现本契约的控制技能或适配器。

在 `control.skill_name` 中设置它的技能名。

在 `control.feature_map_path` 中设置已填好的面向用户的功能地图路径。把 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外再填写，而不是直接编辑复制来的示例。

如果技能、功能地图或某项必需能力缺失、含糊或不完整，复现和修复工作必须关闭即失败（fail closed）。

## 必需能力

### 启动（Bring up）

在请求的测试环境中启动请求的应用版本。

输入：

- 仓库和版本
- 构建或启动模式
- 工作区、账号、夹具（fixture）和功能状态要求
- 产物目录
- 已填好的功能地图路径

返回：

- 会话标识符
- 适配器如何确认了应用和环境正确
- 稳定的应用标记
- 后续调用所需的运行中进程或目标详情
- 任何缺失的能力

适配器必须把目标应用与相似的窗口、shell 或生产实例区分开。

### 驱动 UI

执行真实的用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 调整大小
- 通过应用控件导航

优先使用角色（role）、标签和稳定选择器。只有在新截一张截图之后才使用坐标。

返回每个操作和观察到的状态变化。

不要为了制造症状而设置内部状态、调用隐藏的应用方法、直接写存储或注入 DOM 改动。

### 驱动已建图的功能和状态

在驱动应用之前，阅读相关的功能地图小节。

适配器必须提供方法来：

- 通过用户可见的路径导航到每一个已建图的功能。
- 调用为该功能列出的适配器动作名。
- 在适用时，与默认、悬停、聚焦可见（focus-visible）、激活、禁用、加载中、空、错误、选中、打开、已展开以及功能特有的状态交互。
- 通过安全的夹具数据、权限、开关、服务响应或受支持的测试控件来布置状态。
- 重置该功能，以便进行第二次独立的复现尝试。
- 截取功能地图所指名的截图、视频和只读交叉核对。

使用角色、可访问名称、ARIA 关系、稳定的组件标记和以用途命名的 data 属性。绝不使用生成的 CSS 或 StyleX 类名、动态哈希、子元素索引或脆弱的 DOM 位置。

布置前置条件并不等于获准注入所报告的症状。复现本身仍必须来自真实的用户交互。

### 检查状态

读取状态，以确认 UI 显示了什么。

例子：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果一次查询会改变状态，它就属于「驱动 UI」，且必须代表一个真实的用户操作。

### 截图

把当前应用状态截取到请求的路径。

返回：

- 文件路径
- 截取时间
- 应用标记或窗口标题
- 应当可见内容的简短描述

截图必须展示足够的应用外框（chrome），以证明被测的是正确的应用。

### 录制

围绕完整的复现路径开始和停止一次屏幕录制。

返回：

- 文件路径
- 开始和停止时间
- 录制的窗口或区域
- 是否省略了音频或敏感浮层

录制必须展示有区分度的最终状态，而不只是准备过程或加载画面。

### 清理

停止由适配器创建的进程和会话。

移除一次性用品：

- 浏览器或应用配置文件
- 临时工作区
- 适配器创建的测试账号或夹具
- 调试端口和隧道
- 超过保留期的截取产物

返回哪些被停止、移除、保留，或留给了人工处理。

清理不得删除用户的工作成果。

## 适配器行为

适配器必须：

- 在复现开始前报告能力。
- 报告它能驱动哪些功能地图小节、哪些被阻塞。
- 对基线构建和打补丁构建使用相同的环境输入。
- 把启动失败如实报告为失败。
- 给重试设上限。
- 让密钥远离日志和产物。
- 把截取产物放在仓库之外。
- 支持在两次复现尝试之间使用全新或重置的状态。
- 避免改动生产环境，除非用户明确配置了安全的测试动作。

## 环境转译

在宣布环境受阻之前，用不依赖特定平台的名词重述缺陷，并询问能否在可用环境中安全地测试同样的行为。

例子：

- 指名的浏览器可能意味着任何外部浏览器。
- 指名的按键可能意味着配置好的快捷键。
- 指名的远程主机可能意味着延迟或断开的远程目标。

只有当转译后的尝试测试的是同一个底层行为时才使用它。把它标注为转译证据。当缺失的环境本身是缺陷的一部分时，不要称它为精确复现。

硬件提示、操作系统权限对话框、设备专属 API 和不可用的账号状态可能是真正的阻塞。

## 设置检查

在启用复现自动化之前，运行一次无害的适配器检查：

1. 启动应用。
2. 确认稳定的应用标记。
3. 加载一个已填好的功能地图小节。
4. 通过其用户路径导航到该功能。
5. 通过已建图的适配器动作演练一个可丢弃的状态。
6. 检查由此产生的状态。
7. 截一张截图。
8. 录一小段视频。
9. 清理。

只有当全部九个步骤都成功、且不涉及任何发到源频道的 Slack 消息时，才启用复现工作。
